Metaconcert
on Claustrum

Why a protocol written for one harness belongs in the binary that was built to free a pipeline from one harness — and the four mechanisms it inherits by moving.

one skill source → 5 hosts + a console members as OS processes, not subagents 3 of 5 ceilings gain a lever needs a typed membrane in core

The short version. Metaconcert needs a trigger in a chat session, eight isolated contexts, a model and a tool grant per member, and three stops for a human. Claustrum already ships five of those six. The sixth — a per-member typed membrane — is the one thing worth building.

01

Why here

Metaconcert is Claude-Code-shaped: .claude/agents/, .claude/skills/, the Agent tool, one model family. There is no second runtime for it, and Claustrum is not merely a convenient candidate — it is the machine whose entire premise is “one role source, any harness”.

“Available to anyone who runs the executable” holds for the dispatch, not the trigger: a slash command needs a chat host. The console row above is the honest completion of that sentence, and it has a precedent — the cast questionnaire already specifies an interactive TTY fallback “for people working outside any chat”.

02

What it changes about the membrane

Metaconcert names five ceilings on member independence and finds a lever for one of them. Three of the other four turn out to be properties of dispatch, not of the protocol — and dispatch is exactly what moves.

Self-report becomes a receipt

The protocol states that member self-report is not verification, and that the only mechanical check is the size of the prompt the director built. Claustrum measures from outside the agent: files_changed comes from before/after git snapshots rather than the agent’s word, with cost and duration per job and a job tree linked by a parent id.

The ledger’s weakest fields — prompt-size proxy, wall-clock, per-member cost, which phases actually ran — stop being director-written prose. For a project whose stated bottleneck is thirty entries with a control arm, and whose figures currently live in a gitignored file nobody else can check, that is the main prize.

The outbound check the protocol admits it cannot mechanise

When a member leaks quarantine-class material into a section meant to flow onward, the director must detect it and must not repair it — repairing makes it the classifier. Detection by match against the held set forms no view at all, and the recovery policy is already fully specified: re-dispatch on the original receives, defect in general terms, never quote the material back, one retry, then record leaked.

A runner executes that policy exactly. This is the one place where the tool is better at the protocol than a human director, because the step is one the protocol itself classifies as discipline.

Where the director lives

Metaconcert becomes Claustrum’s second synced skill, with eight roles beneath it — not a role Claustrum runs. The reason is the stops, not role drift.

05

How roles resolve

The protocol is versioned by its author, not by Claustrum releases. So the member set is synced from the metaconcert repo at a pinned version — and a project may still add or override members locally, which is what a new domain needs.

The surface

claustrum mc sync          # fetch pinned upstream
claustrum mc sync --check  # exit 2 on drift (CI)
claustrum mc members       # what resolved, and from where
claustrum mc members --json
claustrum mc new <name>    # local member from template

The director calls mc members --json instead of globbing a directory. It gets the same discovery in every host, plus two things a glob cannot give: the ## MEMBRANE block already parsed and validated, and the source of each member.

Why not vendor the members into the binary

Because then a protocol fix needs a Claustrum release. The member set is the protocol’s content; Claustrum is its runtime. Pinning mc-library: "1.2.0" the way the existing library version is pinned keeps the two release cadences apart and still makes a run reproducible.

It also keeps the direction of authority right: where this page and the metaconcert repository disagree about the protocol, the repository is correct and the sync is what fixes it.

One translation step is real work. Upstream members are Claude-format markdown with a ## MEMBRANE block; Claustrum’s renderer wants role metadata and a typed membrane. The import parses one into the other, which means the MEMBRANE block’s grammar becomes a compatibility surface between two repositories — versioned, and worth a golden test per member.

Status
A design note, not a plan of record. mc-* metaconcert roles are on Claustrum’s explicit “not in v1” list and nothing here is scheduled. Metaconcert itself is efficacy n = 0, so the order that makes sense is a measurement first and an implementation only if it pays off.
